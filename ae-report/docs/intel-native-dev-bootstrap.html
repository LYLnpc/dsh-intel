2. 红线（违反即回滚）

  1. 不修改 new_plugin.ps1 / new_plugin.bat / build_plugin.bat / deploy.bat 本身。要加参数就在新件目录里复制一份改副本。
  2. 不碰 DCStroke（Projects\DCStroke、DC_stroke_Package、BuildOut\DCStroke.aex、已装进 MediaCore 的那份），它只是可供参照的既有实现，不是修改对象。
  3. 不改动本机已安装的任何插件；部署 deploy.bat 需要管理员 + 重启 AE，这一步由用户执行，bot 只交 .aex 产物与部署说明。
  4. 只在 E:\AEDev\Projects\ 下新建目录；不复制 3 大厂算法内核、不反编译任何现有 aex。

3. 已知坑（今天读脚本发现的，能省几轮试错）

  1. deploy.bat 硬编码了 DCStroke.aex：脚本里 if not exist "%SRC%\DCStroke.aex"、copy /Y "%SRC%\DCStroke.aex"。新件不能直接跑它——要么复制一份改文件名，要么手写一条 copy，别直接执行原脚本（它会因为找不到 DCStroke.aex 直接退出，或误拷旧件）。
  2. new_plugin.ps1 拒绝已存在的目标目录：同名件要重建必须先自己处理旧目录（建议改名归档，不要直接删）。
  3. vcxproj 需要 retarget：脚本改完 SDK 相对路径后，首次打开 .vcxproj 可能提示重定向到 v143/x64，按提示确认即可；命令行编译走 build_plugin.bat 不受这个对话框影响。
  4. C4819 警告是常态：SDK 头文件含非 936 代码页字符，build_log.txt 里大量出现，不是错误，只要最后一行是 xxx.vcxproj -> ...aex 就算成功。
  5. build_log.txt 是覆盖写的：每次编译都会冲掉上一次结果，要保留证据就先复制一份。
  6. PiPL 资源依赖 Skeleton 的自定义生成步骤：官方要求"永远从 Skeleton 复制、不要新建空项目"，new_plugin.ps1 已按这条做，别绕开它手搓工程。

4. 第一个件建议（原创、小而完整）

选不依赖 GPU、不依赖多帧缓存的单帧像素/几何效果最稳，例如：

  • 色彩类：自定义曲线/色阶/单色映射（单帧、无历史帧依赖）
  • 几何类：极简描边/轮廓偏移（用 PF_EffectWorld 直接读像素）
  • 噪声类：可粒子化种子的程序噪声叠加（PF_InData.total_time 取时间，不用缓存）

避免第一件就做：多帧缓存、时间重映射、需要 GPU 加速（Metal/CUDA）、需要自定义 UI 面板（那是 CEP 的活）。先把「编译→加载→出效果→撤下」这条闭环走通，再上复杂度。

5. 验收口径（照群规则第 5 条）

  • 交件必须给：.aex 精确路径 + 字节数 + SHA256 + build_log.txt 最后一行 + 一句「装进 AE 后应看到什么」。
  • 没装进 AE 之前一律算进行中，不算完成。
  • 部署说明写给用户，由用户执行（管理员权限 + 重启 AE）。

6. CEP 侧要点（与 aex 不同，几乎没有试错成本）

  • CEP 面板 = CSXS/manifest.xml + HTML/JS 外壳 + 一个 jsx 桥接文件（ExtendScript 与现有 jsx 完全同一套语法与 API）。
  • 关键坑只在 manifest：ExtensionManifest Version 与 RequiredRuntime 的 CSXS 版本号要与目标 AE 版本匹配，CEP 需开启 PlayerDebugMode 才能在未签名时加载。
  • 建议顺序：先让面板能开、能调通一个 evalScript，再往上堆 UI；不要一开始就写完整交互。
